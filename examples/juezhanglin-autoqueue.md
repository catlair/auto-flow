# 燕云十六声 · 觉障林 自动匹配循环

> 一轮：**大厅点开始匹配 → 排队 → 加载页 → 选出生地 → 对局（只空转）→ 战绩表继续 → 积分结算继续 → 花蕊织按 F 再来一局**。
>
> 原目标：**自动排队 → 匹配中不乱点 → 对局中不干扰 → 结算页自动点继续 → 最后按 F 再来一局**，无限循环。
> 全程 **OCR 找文字**（macOS Vision 离线识别），**不截模板**——换分辨率、改窗口大小、
> 游戏更新换皮都不失效。

## 一、流程图

```
start → 判定·对局内（第一级，只有 3 项检测，timeout_s=15）
   case1 「确定退出吗」 → 点「确认」→ 等 2.5s ─────────────┐
   case2 「观战中」     → 按 Esc（vk:53）→ 等 1.5s ────────┤
   case3 「存活」       → 空等 20s ────────────────────────┤
   else（不是对局内）→ 判定·流程界面（第二级，timeout_s=0）─┤
        case1 「获得花蕊织」   → 点「再来一局」→ 等 6s
        case2 「继续」         → 点「继续」→ 等 4s
        case3 「请选择复活点」 → 点「返回」（放弃复活）→ 等 2s
        case4 「出生地」       → 出生地子判定（见下）
        case5 「开始匹配」     → 点「开始匹配」→ 等 5s
        case6 「确定」         → 点「确定」（弹窗兜底）→ 等 1.5s
        else → 空转 0.2s
                                                           └→ 回第一级
```

**为什么分两级**：多路分支上限 6 个 case，而这一局需要的判据有 9 个。按「什么时候会看到」拆开：
对局内（占绝大部分时间）只看 3 项，省 OCR；只有不在对局内时才去跑第二级那 6 项。

**死亡后的处理**（真机确认的两条线）：

| 情况 | 界面 | 脚本动作 |
| --- | --- | --- |
| 开局不久挂掉（有复活机会） | 复活点地图（请选择复活点 / Space 复活(83)） | 点「返回」放弃复活 |
| 没有复活机会 / 复活超时 | 观战中 | **按 Esc → 点「确认」→ 结算**，不干等 |
| 已确认退出 | 弹窗「对局仍在进行…确定退出吗？」 | 点「确认」 |

### 出生地子判定（只在这两个高资源区里选）

```
birth（分支，timeout_s=3）
   case1 「菩提苦海」→ 点「菩提苦海」→ 等 1.5s ┐
   case2 「佛光顶」  → 点「佛光顶」  → 等 1.5s ┤→ 按 Space（前往出生地）→ 等 4s → 回主判定
   else（两区都没读到）→ 直接按 Space ─────────┘
```

- **优先级就是 case 顺序**：两区都在地图上时永远选「菩提苦海」；只有它读不到（被占满/地图刷新不同）
  才选「佛光顶」；两个都读不到就直接按 Space 交给游戏默认。
- 点完区域**再按一次 Space**：点选只负责选区域，`Space 前往出生地` 才是确认。万一点击没生效，
  Space 也会把角色送进默认出生点，不会卡在这张图上。
- `timeout_s=3`：地图文字刚渲染出来要等一下，3 秒内没读到任何区域就直接走，不干等。

## 二、六张截图对应的判据

| 界面 | 判据文字 | 动作 |
| --- | --- | --- |
| 大厅（觉障林详情） | 开始匹配 | 点「开始匹配」 |
| 出生地选择（地图） | 出生地 | 进子判定：菩提苦海 > 佛光顶 > 直接 Space |
| 对局中（HUD） | 存活 | 空等 20s，**什么都不点**（护栏，见下） |
| 全场最佳（MVP 展示） | 继续 | 点「继续」 |
| 战绩表（排名 50/50） | 继续 | 点「继续」 |
| 积分结算（断水·二 +0） | 继续 | 点「继续」 |
| 花蕊织汇总（获得花蕊织 13） | 获得花蕊织 | 按 **F**（再来一局） |
| 任意弹窗 | 确定 | 点「确定」兜底 |

判据都选了**该界面独有**的词：`获得花蕊织`、`玩家信息` 大厅没有，`分数` 只在两张结算页出现。
两个坑是特意避开的：
- **`断水` 不能当判据**——大厅右侧也有「断水·二 1648/1800」，会误判成结算页。
- **`生存时间` 不能当判据**——对局 HUD 里很可能有同名字段，会在对局中误判成战绩表。
  所以改用战绩表的表头 `玩家信息`。
- 排队时按钮变成「Space 退出匹配」，**画面上没有「开始匹配」了**，所以队列期间不会误点重排。

## 三、跑之前

1. 游戏窗口**前台可见、位置固定**；挂机期间别切走（点击/按键都是系统级注入，打给最前面的窗口）。
2. 权限：系统设置 → 隐私与安全性 → **屏幕录制** + **辅助功能**，给 `Auto Flow.app` 勾上。
3. **先单步验证 OCR**：把「找文字点击」单独跑一次「开始匹配」，点中了再挂机。
   游戏字体太艺术化时 Vision 可能读不出——这是本方案唯一的翻车点。
4. **验证 F 键**：`按 F` 是键盘节点（单键按下再释放）。若游戏不吃合成按键（部分全屏游戏
   走 raw input 会忽略），把该节点换成「找文字点击 → 再来一局」即可，逻辑不变。

## 三·四、合成键盘事件对这个游戏无效（真机实锤）

真机日志：17:53:27–17:54:59 之间脚本连续 **13 次**走「获得花蕊织 → 按 F」，
每次间隔 7 秒，**页面纹丝不动**。同一份流程里鼠标点击（点「继续」、点「开始匹配」、点「菩提苦海」）
每次都生效。

结论：**燕云十六声不响应合成键盘事件（raw input），只认鼠标点击。**
所以 v3 起把 `按 F` / `按 Space` 全部换成点击按钮：

| 原来 | 现在 |
| --- | --- |
| 键盘 F（再来一局） | 点「再来一局」 |
| 键盘 Space（前往出生地） | 点「前往出生地」 |

## 三·五、对局中的护栏（真机踩到的坑）

真机首跑时，对局画面被 OCR 误判成「出生地」，于是按了一次 Space——在对局里 Space 是**跳跃**。
所以加了一条 **「存活」** 判据挡在「出生地」前面：对局 HUD 左上角一直有「存活 N」，命中它就只空等 20s。
注意顺序：结算页的「存活分数」也含「存活」，但「继续」排在它前面，所以结算页仍然走「点继续」。

另外判定 `timeout_s` 从 60 降到 15：对局里几分钟没有任何动作是正常的，但一轮 60 秒才闪一次
节点会让人以为「脚本卡死了」。降到 15 秒后画布上能明显看出它在跑，步数预算仍有约 20~29 小时。

## 四、已知边界

0. **分支上限 6 路**，现在正好用满（结算 3 + 出生地 + 排队 + 大厅），所以没有留「确定」弹窗兜底。
   真遇到断线重连之类的弹窗要处理，就把「判定」拆成两个串联的分支节点（第一级判结算、第二级判流程）。
   注意第一级要设 `timeout_s=0`（单次判定就往下走），等待只放在第二级，否则会阻塞后面界面的响应。

1. 对局内脚本**只空转不操作**（觉障林是搜宝撤离，脚本不参与战斗）。要自动打就插「录制回放」。
2. 次数/资源用尽时「开始匹配」可能变灰，脚本会一直点它（不报错）——看到就手动停；
   要严谨可加一个「次数不足/已达上限」文字分支接到 `end`。
3. 单次运行 10000 步上限，撞上限会主动停机并报错（约 84 小时）。
4. 只操作最前台窗口，不能后台多开。
5. 不做内存读写、不注入，纯模拟人手；本模式非 PvP，风险自担。
