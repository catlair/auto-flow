导入方式：Auto Flow → 工作流库 → 导入 → 选 JSON。

## 这几份示例踩过的坑（值得先读）

1. **判据要选「该界面独有」的词**。`断水` 在大厅和结算页都有，用它当判据会误判；
   `生存时间` 对局 HUD 里可能有同名字段，也会误判。最后用的是 `获得花蕊织` / `继续` /
   `存活` / `出生地` / `开始匹配` / `确定退出吗`。
2. **优先级 = case 顺序**。结算类必须排在「开始匹配」前面；对局内的护栏（`存活`）
   必须排在 `出生地` 前面，否则对局画面会被误认成出生地图。
3. **这个游戏不认合成字符按键，认虚拟键码**：`keys=F` 按了 13 次毫无反应，
   `keys=vk:15` 才生效。所以能用鼠标点击的一律用点击，键盘只在没有按钮可点时用 `vk:` 码。
4. **多路分支上限 6 个 case**，判据多了要拆成两级串联：第一级放高频（对局内 3 项），
   第二级放低频（结算 / 大厅 / 地图 6 项），省 OCR。
5. **别让 Auto Flow 窗口盖住游戏目标**：运行期间主窗是鼠标穿透的，识别又读全屏——
   虽然 `core/selfmask` 已经把自身窗口涂黑，但**物理遮挡**仍会让你点不到被盖住的目标。
