# 游戏挂机工作流实战总结

两个跑通的脚本，都在《燕云十六声》里验证过：

| 脚本 | 干什么 | 文件 |
| --- | --- | --- |
| 觉障林排队 | 止戈 → 觉障林（1 人生存·搜宝撤离）无人值守循环 | `examples/juezhanglin-autoqueue.json` |
| 江湖悬赏抢单 | 抢「解决诬陷」悬赏 → 前往做任务 → 话术对决 → 下一单 | `examples/bounty-all.json` |

两个脚本的共同点：**全靠屏幕文字（OCR）+ 窗口锚点坐标**，不读内存、不改游戏文件。

---

## 一、觉障林排队循环

### 流程

```
开始匹配 → 排队 → 加载 → 选出生地 → 对局 → 结算页 → 再来一局（自动重新排队）
```

出生地只在**菩提苦海 / 佛光顶**里选一个。

### 界面判据（每个都必须唯一）

| 界面 | 判据 |
| --- | --- |
| 大厅 | `开始匹配` |
| 排队中 | `匹配中` |
| 出生地地图 | `出生地` |
| 对局中 | `复活机会`（只在 HUD 里出现） |
| 观战中 | `观战中` |
| 退出确认弹窗 | `确定退出吗` |
| 结算页 | `继续` |
| 奖励页 | `获得花蕊织` + `再来一局` |
| 复活点选择 | `请选择复活点` |

**绝对不要用**：`断水`、`生存时间`、`存活分数`、加载页的诗句（每次随机）。

> `存活` 曾经被用来判「对局中」，结果被结算页的 `存活分数` 命中——两个字的词一定要检查它还会出现在哪。

### 几个游戏机制

- **复活免费**，所以复活点直接点右下角（`win_br (-29,-30)`）。
- **观战界面按 Esc 无效**，只能点右上角的退出图标（`win_tr (-20,+46)`）才弹确认框。
- **「再来一局」会自动重新排队**，不用回大厅。
- 结算页顺序：个人战况 → 加分界面 → 奖励界面（MVP 前面还会多一页）。
- 结算链是**盲点 + 复查**：点右下 → 等 3.5s → 查「再来一局」，最多 3 次。

## 二、江湖悬赏抢单

### 流程

```
开右上角菜单 → 面板往下拖 → 点「悬赏」→ 点「营生」
  → 循环：右键收起面板 → 点「刷新」→ 轮询卡片 → 点「解决诬陷」→ Space 接取
  → 分流：有「前往」= 诬陷类 → 做任务
          有「进入世界」= 治疗类 → X 放弃 → Space 确认 → 回页面重抢
  → 做任务（死顺序）：前往 → 寻路3.5s → F → Space×3 → 点「话术争锋」→ 连按 F → 「继续」→ Space
  → 回大世界 → 抢下一单
```

### 关键坐标（相对窗口锚点）

| 东西 | 锚点 + 偏移 |
| --- | --- |
| 右上角菜单图标 | `win_tr (-23, +48)`（先悬停 0.4s 浮出「菜单」，再点一下） |
| 面板拖动起点 | `win_tr (-150, +430)`，往上拖 -260 |
| 「刷新」按钮 | `win_br (-45, -30)`（盲点，不用 OCR） |

### 键位（macOS 虚拟键码，游戏只认这个）

| 键 | 写法 |
| --- | --- |
| Space | `vk:49` |
| F | `vk:3` |
| X | `vk:7` |
| R | `vk:15` |
| Esc | `vk:53` |

### 搜索范围

- **卡片**：窗口横向 6%~68%、纵向 18%~82%。左边 6% 是为了避开左侧任务栏。
- **「悬赏」这行**：右侧 55%~100%（左侧任务栏里也有「悬赏」两个字）。
- **「前往」「进入世界」「放弃悬赏」**：右侧 40% 以后（任务栏里也有「前往」）。

## 三、江湖弈（自走棋）单人 AI 循环

### 为什么这个脚本用「状态分派」而不是顺序

前两个脚本是死顺序：界面出现的先后基本固定。江湖弈不是——同一回合里
「选棋局变数」「选装备」「局内买卖」「战斗」的先后会变，死顺序一定错位。

所以主循环是**每秒判一次现在在哪一屏**，六路分派（分支节点上限就是 6）：

| 判据 | 那一屏 | 动作 |
| --- | --- | --- |
| `开始匹配` | 大厅 | 点「单人AI」→ 点「开始匹配」 |
| `弈子概率` | 局内（能买） | 做一遍买卖动作，然后等 15 秒 |
| `请选择一个棋局变数` | 三选一 | 点最左那张卡 |
| `再来一局` | 结算末页 | 按 F |
| `继续观战` | 半步登天（兜底） | 按 F |
| `继续` | 名次页 | 按 Space |

都不命中 → 空转 1 秒（加载、开局第一场、特殊界面都走这条）。

**分支顺序是有语义的**：「再来一局」必须排在「继续」之前，因为那一页**同时有**
「继续」两个字；顺序反了就永远走不到「再来一局」。同理「继续观战」要排在「继续」前面。

### 没有「商店阶段」——购买栏一直都在

这是这个脚本最容易写错的地方。底部购买栏（`弈子概率` / `购买经验` / `刷新` / 5 张卡）
**除了第一场和特殊界面（三选一 / 奇遇排队 / 结束时的 buff），全程都在**，随时能买。

所以：

- 不能拿「购买栏在不在」划分阶段；
- 更不能「等购买栏消失」——它一整个对局都不消失，会白等到超时。

做法是**按时间循环**：看到 `弈子概率` 就把买卖动作做一遍，然后等 15 秒再回主循环。
15 秒是「一轮大概多长」的粗估；期间不判界面，所以特殊界面最多晚 15 秒响应——
它们有 25~30 秒倒计时，来得及。

### 局内买卖动作

```
菜单开着吗（有「一键穿戴」）？→ 没开才点「快捷操作」
  → 点「一键穿戴」
菜单还开着吗（有「一键提升」）？→ 没开再点「快捷操作」
  → 点「一键提升」→ 有「合成预览」就点勾选框
  → 有菱形图标就点它（买那张卡）
  → 回合 ≥ 3 按 F 一次；回合 ≥ 5 再按一次（满级自动停）
```

### 键位

F = `vk:3`，Space = `vk:49`。

## 四、踩过的坑（这一节比流程更值钱）

### 1. 判据必须唯一，否则会出现「自洽的错误循环」

同一个词在屏幕上出现多处，判断就会永远成立，脚本会在错误的状态里一直转。

真实案例：

| 判据 | 还被谁命中 | 后果 |
| --- | --- | --- |
| `存活` | 结算页的 `存活分数` | 卡在结算页 |
| `悬赏` | 左侧任务栏 | 面板没滚到底就以为看见了，点进了别的功能 |
| `前往` | 大世界任务栏 | 每轮都点「前往」，寻路 → 再点，死循环 |
| `解决诬陷…` | 左侧任务栏 | 人站在湖边打伞，脚本却一直在「刷新 → 判有卡」 |

**对策**：用「那个界面独有」的字（`放弃悬赏` 只在已接取的详情页；`玩法说明` 只在悬赏页面），或者加搜索范围。

### 2. 搜索范围是双刃剑

裁剪能提速、能排干扰，但**边界压太紧会切掉目标文字本身**，而且表现是静默失效：

> 第一张卡片的字从窗口 7.3% 开始，裁剪设成 8% → 首字被切掉 → 识别结果不含「解决诬陷」→
> 列表里只有一张卡时永远抢不到（有两三张时才偶尔命中）。

**对策**：边界卡在「干扰物」和「目标」之间的空白处，别贴着目标。

### 3. 合成输入可能被游戏过滤

- **滚轮**：手动滚轮正常，脚本的滚轮完全没反应。全局投递、`CGEventPostToPid` 直接投给进程——**两种都被丢掉**。
- **替代方案**：**拖拽列表**（按住 → 分步移动 → 松开）。必须分步，一步跳到终点游戏只看到光标瞬移。
- **键盘**：合成字符键没用，**虚拟键码有效**（`vk:49` 等）。

### 4. 悬停有副作用

奖励图标那一排**悬停就会弹物品说明**，把界面挡住。所以点完卡片要立刻把光标挪到空白处。

### 5. 「按顺序」还是「按界面判断」

当同一个画面同时是多个步骤的载体时（比如「F 诬陷悬赏」是常驻提示，接取页 / 大世界 / 任务开始页长得一模一样），**按界面判断必然错**。

对策：这段改成**死顺序**执行，只在真正唯一的判据上保留分支（比如「继续」只在胜负结算页出现）。

### 6. 每一步都要能发现自己「不在该在的地方」

错误状态会自洽地循环下去。所以在循环入口加一道状态检查：

> 进抢单循环前先判「有『玩法说明』吗」，没有就回去重新开菜单。

### 7. 点击后立刻做下一步，别等渲染

接取只认「当前选中的是哪张卡」，不需要等详情面板渲染完。点完卡片 60~100ms 就按 Space。

### 8. 固定位置的按钮用盲点，变化的内容用 OCR

> 2026-10 修正：盲点只在**目标位置确实固定**时成立。界面元素会随内容移动
> （例如左侧那一列随装备格数量上下移）时，一律改用文字锚点；有模板可匹配的
> 一律用「找图点击」。详见第 15 条。

「刷新」按钮位置固定 → 窗口锚点盲点，省一次全屏识别（约 0.4 秒）。
卡片内容每次变 → OCR + 搜索范围。

### 9. 绑定窗口，别靠「最前面的那个」

默认取「最前面那个不属于自己的窗口」。只要浏览器、访达或任何弹窗抢到前台，锚点就
整体算到另一个窗口上——**点击全歪而且不报错**，表现只是「点了没反应」。
标题栏的「绑定窗口」选到游戏之后只认那一个：它不在前台也照它的几何算，
找不到就拒绝点击（宁可不点，也不要瞎点）。

### 9.5 窗口锚点让脚本跟着窗口走

用 `win_tl / win_tr / win_bl / win_br` + 偏移，而不是绝对坐标。游戏窗口被移动、改大小都不影响。

### 10. 用工具排查，别靠猜

卡住时**先看「看屏幕」**（诊断面板）：它一次给出窗口矩形 + 全屏 OCR 的全部文本及坐标
（带窗口百分比）。判据不成立只有两种可能——没识别到、或被搜索范围滤掉——以前这两种
在用户那边看起来都是「明明在屏幕上」，只能靠猜。

- **点完校验**：找文字点击节点有 `verify_text`（点完等某段文字出现，没等到就重试，
  再不行报警/停止）。点击「没生效」是最常见的静默失败，别靠手接条件节点。
- **卡住检测**：执行器发现同一个节点本轮跑超过 20 次会打 WARNING（界面横幅 + 诊断面板）。
- **重新加载**：改完磁盘上的 JSON 点一下就读，不用另存新的一条（以前两天攒了 20 个版本号）。

### 11. 交付前跑一遍自检

```bash
.venv/bin/python scripts/check_workflow.py --lib
```

查悬空连线、重复出口、没接线的出口、不可达节点、分支缺值。改工作流最容易出的错就是**改了节点 uid 却没改边**。

### 12. 发布新库 id，不要改旧文档

App 不会从磁盘重新加载工作流。每次迭代都**发布成新的 library id**，旧的一起删掉，否则容易点到旧版本跑。

### 13. 同一个键在不同界面含义不同，判据错一次就白花钱

江湖弈里 `F` 至少有三种含义：商店里 = 购买经验（4 乌鹭币一次）、
结算页 = 退出、末页 = 再来一局。

所以「按 F」这件事本身没有意义，**先认界面再按键**。踩过的具体坑：
结算页判据写「继续观战」，赢了的那一局（只有「F 退出」、没有「继续观战」）
判不出来 → 空转；而如果把判据放宽成「退出」，战斗界面右上角也有「退出」，
就会在局内反复按 F = 反复买经验。

**做法**：用**位置**把同名文字分开——结算页的「退出」在右下角，
战斗界面的在右上角，判据带上搜索范围（右 70%~100%、下 78%~100%）。

### 14. 拿来做判据的文字，可能同时是别的界面的表头

「棋局变数」既是选卡页的标题，也是结算表格的列名
（血量 / 玩家信息 / 阵容 / 棋局变数 / 联结）。用它当判据，脚本在结算页
反复命中、把「点最左卡」点到结算表上，转圈转到天荒地老。

**做法**：判据尽量取**整句**（「请选择一个棋局变数」），而不是关键词。
关键词越短，撞车的概率越高。

### 15. 盲点只在「目标位置固定」时成立；锚点固定但目标浮动时，点还得跟着匹配走

两次翻车，两种原因：

1. **锚点本身在动**：「快捷操作」那一列会随装备格数量上下移动，写死 `(85,111)`
   有时点空。改成点文字（文字会跟着移动）。
2. **锚点固定、目标浮动**：菱形图标会出现在**某一张卡**上，第几张不固定。
   先用模板匹配判断「在不在」、再点一个固定坐标——结果图标在第 3 张、点到了第 4 张，
   **买错人**。改成 `图像匹配点击`：找和点是一步，点的是匹配到的位置。

所以有模板可匹配的东西，**永远用「找图点击」而不是「判断存在 + 点坐标」**。

### 16. 等「某段文字消失」比固定延时可靠

商店阶段有多长取决于操作速度，固定延时要么白等要么太短。
`等待文字消失` 节点：轮询到它不见为止（带超时）。这是主循环里
防止「每秒重做一遍」的关键。

### 17. 正则判据：表达「回合数 ≥ 3」

顶部回合数是 `3-4` / `2-5` 这种格式，包含关系写不出来（`3-` 会命中 `13-`）。
条件节点的「文字匹配」支持正则：`^[3-9]-\d`。

### 18. 先确认「这个 UI 元素的生命周期」，再拿它当判据

江湖弈里我把底部购买栏当成「商店阶段才有」，还写了「等它消失」。
实际它**除第一场和特殊界面外全程都在**——于是每轮白等 90 秒才超时继续，流程被拖死。

教训：拿某个元素当阶段判据之前，先问清楚三件事——

1. 它什么时候**出现**？
2. 它什么时候**消失**？
3. 它会不会**一直在**？

「一直在」的元素不能用来划分阶段，只能用来表示「处于某个大状态」（比如「在局内」）。
如果需要的其实是「每轮做一次」，那用时间循环，别去等一个永远不会变的状态。

### 19. 「跑满 N 轮就停」的起点，必须选在手上没活的时候

轮次起点同时就是**停止点**：执行到它之前发现已满 N 轮，就停在那里。

所以它不能选在“任务进行到一半”的节点上。真事故（2026-10-25）：悬赏脚本把起点设在
「点「前往」」——可那是在**接取悬赏之后**。跑满 100 轮时正好停在刚接完单、还没去做的位置，
把一单悬赏白白占在手里：自己没做完，别人也接不到。

**选点原则**：停在那个节点时，「手上应该什么都没有」。悬赏脚本的正确选择是
「移到右上角图标（挑下一单之前）」——它只在「没有已接取的悬赏 / 刚做完一单回到大世界」时才执行。

这类「停止位置」问题在测试里看不出来，只有真跑到上限才会暴露。标完起点最好手动设 2 轮跑一遍，
看看停下时的界面干不干净。

### 20. 轮次要「开始 + 结束」配对计数，不要拿单点计数

拿一个节点计数看起来简单，但**单点计数会把「意图」当成「事实」**：

- 点「开始匹配」→ 点完没进对局（点空了/还在大厅）→ 却已经算了一轮；
- 结算页翻三页都点「继续」→ 一局算出三轮。

正确做法（用户提的）：配一对标记，**先见到开始、再见到结束**才算一整轮。

**开始标记要把“所有能开一局的地方”都标上**。第一局走「开始匹配」，第 2 局往后都是
「再来一局」开的——只标前者，第 2 局就没有开始配对了，永远停在 1 轮。
（真机反馈 2026-10-25：「你把点开始匹配当开始，那点中间都是再来一局」。）
重复的开始不另算（连点几次开始匹配仍是同一局），重复的结束也不另算（翻页仍是一局）。

停止也发生在结束那一刻（上限在结束标记之前判），所以跑满 N 轮 = 正好 N 局，
而且停下来的位置是干净的（结算页/大世界），不会把没打完的一局丢在那儿。

### 21. else/兜底分支要能自己走出去，别原地空转

状态机里最危险的不是判错，而是**判不到**：所有 case 都不匹配时落到 else，
而 else 只是「等 1 秒再看一遍」，于是永远在同一屏上打转。

真机（2026-10-25 江湖弈）：「半步登天」晋级页没单独判 → else 空转 → 卡死。

**兜底要点**：把 else 接到一个「宽泛但通用」的出口检查上，而不是直接回到主判定。
燕云的通用出口是「右下角有『退出』」（结算页、晋级页、各类结算/弹窗页都有），
认到就按 F 退一步，认不到再空转。这一步能把大部分没预料到的页面带出死循环。

## 五、写新脚本的推荐顺序

1. **先手动走一遍**，把每个界面的「独有文字」记下来（这一步最关键，能省掉后面一半的返工）。
2. 画流程时区分两类节点：**固定顺序的**（死顺序直连）和**需要判断的**（只留唯一判据）。
3. 每个判断都问一句：「这个词还在别的地方出现吗？」
4. 用 OCR + 窗口锚点先跑通，再考虑裁剪提速。
5. 每加一道判断，就在循环入口加一道「我在该在的地方吗」的检查。
6. 跑通后把坐标、范围、判据整理成注释（`note` 节点），下次改的时候不用重新量。
