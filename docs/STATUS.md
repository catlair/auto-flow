## 近期计划（无主次排序）

- 📋 **版本号要能区分构建**（用户 2026-10-21 提，约「下次」做）：标题栏恒显示
  `v0.1.0`，同一天装了好几轮新版也看不出装的是哪一份，用户没法自证「新功能到底进没进包」。
  做法：打包时把构建时间（或短 commit）拼进 `CFBundleShortVersionString` / 标题栏，例如
  `v0.1.0+2026-10-21 18:38`。改 `tauri/src-tauri/tauri.conf.json` 的 version 与
  `rpc/__init__.py` 的 `__version__` 两处要同步（标题栏的 v 号来自后端 app.info）。

- 📋 工作流库补三项：**删除时提示有哪些定时任务引用了它**（定时按路径引用，
  删掉之后下次触发才报 `workflow_missing`）、**搜索 / 分组**（条目 >50 之后
  只能靠按最近修改排序翻）、**「先停再切」的一键操作**（现在运行中切一份会被拒，
  用户得自己先按停止）
- 📋 标题栏两个圆点挨在一起（真机目视发现）：未保存时是
  `未命名工作流 ● ● 已连接 v0.1.0`，「未保存」和「已连接」两个状态点分不清。
  需要一次设计决定（把连接状态移到最右，或把未保存写成文字），不是随手能调的
- 📋 录制库补四项：**库目录可配置**（现在固定 `{app_dir}/recordings/`，跨设备
  复用只能手工拷目录）、**引用计数索引**（删一条录制时提示有几个节点在引用，
  现在是现扫工作流算出来的，节点多了要扫一遍）、**删除要不要进废纸篓**
  （现在 `record.lib.delete` 是 `os.remove` **真删**，与工作流库「进废纸篓、
  可从 Finder 捞回」不一致；录制文件可能很大，当初没照搬——需要一次取舍）、
  **「直接编辑」期间没有「放弃改动」的出口**（编辑是即时写回的，后悔只能靠
  `record.undo`，撤销栈上限 20 格；要真正的编辑会话得在库侧做影子文件 + 提交/回滚）
- 📋 托盘增强：现在只有「显示主窗口 / 开始录制 / 退出」三项。可按需再加
  定时任务状态、直接跑某份工作流——但每加一项都要先答"窗口藏起来时用户怎么
  知道它失败了"（托盘没有地方显示错误）
- 📋 条件分支扩展：比较类条件（变量 / 上一节点结果）而非仅「存在性检测」。
  「与 / 或 组合多个检测」已由 `condition_group` 覆盖，剩下的是**比较**这一类
- 📋 环提示增强：把「标出环」开关的**状态持久化**（现在重启应用回到默认关），
  以及在工具栏之外再给个入口——它现在不主动暴露，用户不知道有这个按钮就等于没有
- 📋 画布编辑增强：框选、复制粘贴、对齐吸附、节点分组
- 📋 工作流变量系统：跨节点传值（计划书 §workflow_vars 曾有占位）
- 📋 Windows 支持：core 逻辑平台无关，输入层需按平台抽象（pynput 可跨）
- 📋 视觉模型按需分发：opencv/onnxruntime 占 sidecar 体积 200MB+，可拆可选包
- 📋 公证：需 `APPLE_ID / APPLE_APP_PASSWORD / APPLE_TEAM_ID`，脚本参数位已留
- 📋 录制侧直接拿汉字：唯一方向是 AX 轮询 `kAXValueAttribute` 差分，但终端/
  画布类应用不适用且不知道插入位置，暂不做（见 recorder.md 已知问题）
