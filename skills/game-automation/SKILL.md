# 游戏挂机工作流实战总结

两个跑通的脚本，都在《燕云十六声》里验证过：

| 脚本 | 干什么 | 文件 |
| --- | --- | --- |
| 觉障林排队 | 止戈 → 觉障林（1 人生存·搜宝撤离）无人值守循环 | `examples/juezhanglin-autoqueue.json` |
| 江湖悬赏抢单 | 抢「解决诬陷」悬赏 → 前往做任务 → 话术对决 → 下一单 | `examples/bounty-all.json` |

两个脚本的共同点：**全靠屏幕文字（OCR）+ 窗口锚点坐标**，不读内存、不改游戏文件。

---

## 一、觉障林排队循环

### 流程

```
开始匹配 → 排队 → 加载 → 选出生地 → 对局 → 结算页 → 再来一局（自动重新排队）
```

出生地只在**菩提苦海 / 佛光顶**里选一个。

### 界面判据（每个都必须唯一）

| 界面 | 判据 |
| --- | --- |
| 大厅 | `开始匹配` |
| 排队中 | `匹配中` |
| 出生地地图 | `出生地` |
| 对局中 | `复活机会`（只在 HUD 里出现） |
| 观战中 | `观战中` |
| 退出确认弹窗 | `确定退出吗` |
| 结算页 | `继续` |
| 奖励页 | `获得花蕊织` + `再来一局` |
| 复活点选择 | `请选择复活点` |

**绝对不要用**：`断水`、`生存时间`、`存活分数`、加载页的诗句（每次随机）。

> `存活` 曾经被用来判「对局中」，结果被结算页的 `存活分数` 命中——两个字的词一定要检查它还会出现在哪。

### 几个游戏机制

- **复活免费**，所以复活点直接点右下角（`win_br (-29,-30)`）。
- **观战界面按 Esc 无效**，只能点右上角的退出图标（`win_tr (-20,+46)`）才弹确认框。
- **「再来一局」会自动重新排队**，不用回大厅。
- 结算页顺序：个人战况 → 加分界面 → 奖励界面（MVP 前面还会多一页）。
- 结算链是**盲点 + 复查**：点右下 → 等 3.5s → 查「再来一局」，最多 3 次。

## 二、江湖悬赏抢单

### 流程

```
开右上角菜单 → 面板往下拖 → 点「悬赏」→ 点「营生」
  → 循环：右键收起面板 → 点「刷新」→ 轮询卡片 → 点「解决诬陷」→ Space 接取
  → 分流：有「前往」= 诬陷类 → 做任务
          有「进入世界」= 治疗类 → X 放弃 → Space 确认 → 回页面重抢
  → 做任务（死顺序）：前往 → 寻路3.5s → F → Space×3 → 点「话术争锋」→ 连按 F → 「继续」→ Space
  → 回大世界 → 抢下一单
```

### 关键坐标（相对窗口锚点）

| 东西 | 锚点 + 偏移 |
| --- | --- |
| 右上角菜单图标 | `win_tr (-23, +48)`（先悬停 0.4s 浮出「菜单」，再点一下） |
| 面板拖动起点 | `win_tr (-150, +430)`，往上拖 -260 |
| 「刷新」按钮 | `win_br (-45, -30)`（盲点，不用 OCR） |

### 键位（macOS 虚拟键码，游戏只认这个）

| 键 | 写法 |
| --- | --- |
| Space | `vk:49` |
| F | `vk:3` |
| X | `vk:7` |
| R | `vk:15` |
| Esc | `vk:53` |

### 搜索范围

- **卡片**：窗口横向 6%~68%、纵向 18%~82%。左边 6% 是为了避开左侧任务栏。
- **「悬赏」这行**：右侧 55%~100%（左侧任务栏里也有「悬赏」两个字）。
- **「前往」「进入世界」「放弃悬赏」**：右侧 40% 以后（任务栏里也有「前往」）。

## 三、踩过的坑（这一节比流程更值钱）

### 1. 判据必须唯一，否则会出现「自洽的错误循环」

同一个词在屏幕上出现多处，判断就会永远成立，脚本会在错误的状态里一直转。

真实案例：

| 判据 | 还被谁命中 | 后果 |
| --- | --- | --- |
| `存活` | 结算页的 `存活分数` | 卡在结算页 |
| `悬赏` | 左侧任务栏 | 面板没滚到底就以为看见了，点进了别的功能 |
| `前往` | 大世界任务栏 | 每轮都点「前往」，寻路 → 再点，死循环 |
| `解决诬陷…` | 左侧任务栏 | 人站在湖边打伞，脚本却一直在「刷新 → 判有卡」 |

**对策**：用「那个界面独有」的字（`放弃悬赏` 只在已接取的详情页；`玩法说明` 只在悬赏页面），或者加搜索范围。

### 2. 搜索范围是双刃剑

裁剪能提速、能排干扰，但**边界压太紧会切掉目标文字本身**，而且表现是静默失效：

> 第一张卡片的字从窗口 7.3% 开始，裁剪设成 8% → 首字被切掉 → 识别结果不含「解决诬陷」→
> 列表里只有一张卡时永远抢不到（有两三张时才偶尔命中）。

**对策**：边界卡在「干扰物」和「目标」之间的空白处，别贴着目标。

### 3. 合成输入可能被游戏过滤

- **滚轮**：手动滚轮正常，脚本的滚轮完全没反应。全局投递、`CGEventPostToPid` 直接投给进程——**两种都被丢掉**。
- **替代方案**：**拖拽列表**（按住 → 分步移动 → 松开）。必须分步，一步跳到终点游戏只看到光标瞬移。
- **键盘**：合成字符键没用，**虚拟键码有效**（`vk:49` 等）。

### 4. 悬停有副作用

奖励图标那一排**悬停就会弹物品说明**，把界面挡住。所以点完卡片要立刻把光标挪到空白处。

### 5. 「按顺序」还是「按界面判断」

当同一个画面同时是多个步骤的载体时（比如「F 诬陷悬赏」是常驻提示，接取页 / 大世界 / 任务开始页长得一模一样），**按界面判断必然错**。

对策：这段改成**死顺序**执行，只在真正唯一的判据上保留分支（比如「继续」只在胜负结算页出现）。

### 6. 每一步都要能发现自己「不在该在的地方」

错误状态会自洽地循环下去。所以在循环入口加一道状态检查：

> 进抢单循环前先判「有『玩法说明』吗」，没有就回去重新开菜单。

### 7. 点击后立刻做下一步，别等渲染

接取只认「当前选中的是哪张卡」，不需要等详情面板渲染完。点完卡片 60~100ms 就按 Space。

### 8. 固定位置的按钮用盲点，变化的内容用 OCR

「刷新」按钮位置固定 → 窗口锚点盲点，省一次全屏识别（约 0.4 秒）。
卡片内容每次变 → OCR + 搜索范围。

### 9. 窗口锚点让脚本跟着窗口走

用 `win_tl / win_tr / win_bl / win_br` + 偏移，而不是绝对坐标。游戏窗口被移动、改大小都不影响。

### 10. 用工具排查，别靠猜

卡住时**先看「看屏幕」**（诊断面板）：它一次给出窗口矩形 + 全屏 OCR 的全部文本及坐标
（带窗口百分比）。判据不成立只有两种可能——没识别到、或被搜索范围滤掉——以前这两种
在用户那边看起来都是「明明在屏幕上」，只能靠猜。

- **点完校验**：找文字点击节点有 `verify_text`（点完等某段文字出现，没等到就重试，
  再不行报警/停止）。点击「没生效」是最常见的静默失败，别靠手接条件节点。
- **卡住检测**：执行器发现同一个节点本轮跑超过 20 次会打 WARNING（界面横幅 + 诊断面板）。
- **重新加载**：改完磁盘上的 JSON 点一下就读，不用另存新的一条（以前两天攒了 20 个版本号）。

### 11. 交付前跑一遍自检

```bash
.venv/bin/python scripts/check_workflow.py --lib
```

查悬空连线、重复出口、没接线的出口、不可达节点、分支缺值。改工作流最容易出的错就是**改了节点 uid 却没改边**。

### 12. 发布新库 id，不要改旧文档

App 不会从磁盘重新加载工作流。每次迭代都**发布成新的 library id**，旧的一起删掉，否则容易点到旧版本跑。

## 四、写新脚本的推荐顺序

1. **先手动走一遍**，把每个界面的「独有文字」记下来（这一步最关键，能省掉后面一半的返工）。
2. 画流程时区分两类节点：**固定顺序的**（死顺序直连）和**需要判断的**（只留唯一判据）。
3. 每个判断都问一句：「这个词还在别的地方出现吗？」
4. 用 OCR + 窗口锚点先跑通，再考虑裁剪提速。
5. 每加一道判断，就在循环入口加一道「我在该在的地方吗」的检查。
6. 跑通后把坐标、范围、判据整理成注释（`note` 节点），下次改的时候不用重新量。
