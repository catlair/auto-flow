# Auto Flow 权限引导（macOS）

Auto Flow 的 Python sidecar 要控制鼠标/键盘、读取屏幕，必须获得 macOS 的**辅助功能 /
输入监控 / 屏幕录制**三项授权。本页说明每项的作用、不授予的后果，以及如何授予。

> 对应迁移计划书 §11 / §12 / P0-S。授权一旦授予，只要 App 的 **designated requirement**
> （MacDev 身份 + bundle id `com.catlair.autoflow`）不变，就跨重新构建持久，无需重授权。

---

## 1. 三项权限分别做什么

| 权限 | 系统设置位置 | 不授予的后果 |
| --- | --- | --- |
| **辅助功能 Accessibility** | 隐私与安全性 → 辅助功能 | 无法驱动全局鼠标点击 / 键盘输入（运行 / 录制回放失效） |
| **输入监控 Input Monitoring** | 隐私与安全性 → 输入监控 | 录制时捕获不到键盘事件（`key` 类事件缺失） |
| **屏幕录制 Screen Recording** | 隐私与安全性 → 屏幕录制 | 图像/OCR/YOLO 节点无法截取屏幕（`vision.grab_screen_bgr` 失败） |

前端在缺失权限时会弹出 `PermissionBanner`（订阅 `permission.changed`），点「打开设置」即调用
`app.openPermissionSettings` 跳到对应面板。

---

## 2. 如何授予

### 方式 A：在 App 内一键跳转（推荐）
打开 Auto Flow → 顶部权限横幅点「打开设置」→ 系统设置自动定位到对应权限项 →
勾选 **Auto Flow**（或 `autoflow-tauri`）→ 关闭再重开 App 让授权生效。

### 方式 B：手动到系统设置
1. 苹果菜单 → **系统设置** → **隐私与安全性**。
2. 依次进入 **辅助功能 / 输入监控 / 屏幕录制**。
3. 点 `+` 或勾选列表里的 **Auto Flow**；若列表里只有嵌套二进制，请用方式 A（系统设置只能选
   `.app` 包本身，选包内的 sidecar 嵌套文件会被拒，见 §12 坑）。
4. 授权后**完全退出并重新打开** App（权限在进程启动时读取）。

> 屏幕录制最稳的授予方式是在 App 内点「打开设置」走系统弹窗点允许（首次弹窗在 App 请求时出现）。

## 3. 已知坑（重要）

- **屏幕录制预检「假阴性」**：`CGPreflightScreenRecordingAccess()` 对调用进程所在会话敏感，
  后台 / 非 Aqua 会话一律返回 `false`。**以你在自己的 GUI(Aqua) 会话里查询为准**
  （App 内 `app.info` 或系统设置看到的是真值），别被 agent / SSH 侧读到的 `false` 误导。
- **改源码后授权是否失效**：MacDev 自签下 TCC 按 designated requirement（身份 + id，**不含
  CDHash**）匹配，因此改 Python 源码重构建仍匹配 → 授权持久；只有 ad-hoc 签名（无身份）才需换
  CDHash 后重授权。
- **首次打开未公证的 App**：若只做了 MacDev 签名、未走 notarization，macOS 可能弹「无法验证
  开发者」。解决：右键 → 打开，或 `xattr -dr com.apple.quarantine /Applications/Auto\ Flow.app`，
  或运行 `./scripts/sync_app.sh`（会自动去 quarantine）。
- **强化运行时会拦下 PyInstaller 的 dylib（必看）**：公证要求 `--options runtime`，但强化运行时
  默认开启**库校验**——要求进程加载的 dylib 由同一 Team 或 Apple 签名。而 PyInstaller onedir 的
  `_internal/*.dylib`（含 `libpython3.12.dylib`）是 **ad-hoc 签名、无 Team ID**，于是 `dlopen`
  直接拒绝并报 `different Team IDs`，sidecar 静默起不来。
  解法：给 sidecar 签名时带 `tauri/src-tauri/entitlements-sidecar.plist`
  （`com.apple.security.cs.disable-library-validation`），豁免库校验。这样既能保留 runtime
  （公证所需），又能加载 Python 共享库。`scripts/sign_tauri_app.sh` 已内置该逻辑。

---

## 4. 部署与签名（P3）

- 构建：`cd tauri && npm run tauri build` → `Auto Flow.app`（位于
  `tauri/src-tauri/target/release/bundle/macos/`）。
- 签名：`bash scripts/sign_tauri_app.sh`（MacDev 双签 + 强化运行时 + 安全时间戳；自底向上先签
  嵌入 sidecar 再签 `.app` 外壳，确保嵌套二进制也带 runtime）。
- 公证（可选，需 Apple 开发者凭证）：
  ```bash
  APPLE_ID=you@icloud.com APPLE_APP_PASSWORD=xxxx APPLE_TEAM_ID=XXXXXXXXXX \
    bash scripts/sign_tauri_app.sh
  ```
  脚本会用 `xcrun notarytool` 提交并 `stapler staple` 票据到 `.app`。
- 安装到 `/Applications`：`bash scripts/sync_app.sh`（固定路径，TCC 授权稳定）。

## 5. 排障：sidecar 连不上（「请求授权失败」/「无法连接后端 sidecar」）

**现象**：顶部权限横幅三项全 ✗，点「去授权」报错。

⚠️ 这往往**不是权限问题**，而是 Python sidecar 压根没起来——权限读不到，自然全是 `false`。
先按下面查 sidecar，别急着去系统设置勾权限。

### 自查顺序

1. **看横幅首行**。Rust 侧现在会给出真实原因，例如：
   ```
   sidecar 启动失败：No such file or directory (os error 2)
   （查找路径 /Applications/Auto Flow.app/Contents/Resources/autoflow-sidecar/autoflow-sidecar）
   ```
   完整信息（含 sidecar 最近 stderr）会打到控制台：App 内「开发 → 打开 DevTools」。

2. **核对 sidecar 是否真在该路径**：
   ```bash
   ls "/Applications/Auto Flow.app/Contents/Resources/autoflow-sidecar/"
   ```
   应看到 `autoflow-sidecar` 可执行文件与 `_internal/` 目录。

3. **若落在 `Contents/Resources/resources/autoflow-sidecar/`（多一层 `resources`）**，
   说明装的是**旧构建**：`bundle.resources` 曾写 `resources/autoflow-sidecar/**`，
   Tauri 会原样保留目录结构，导致双 `resources` 错位（P1-5 已改为 `autoflow-sidecar/**/*`）。

### 最常见原因：改完代码没重新部署

重新构建后**必须再跑一次** `bash scripts/sync_app.sh`，否则 `/Applications` 里仍是旧 `.app`。
推荐一条龙：

```bash
cd tauri && npm run tauri build
bash scripts/sign_tauri_app.sh
bash scripts/sync_app.sh
```

### 历史坑：错误信息显示「…：undefined」

Tauri `invoke` 失败时 reject 的值是 Rust `Err(String)` 的**裸字符串**，不是 `Error` 对象；
直接取 `.message` 会得到 `undefined`，界面就成了「请求授权失败：undefined」。
现已统一走 `errMessage()` 归一化（string / Error / 带 message 的对象都能取到文案）。
