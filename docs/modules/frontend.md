## 设计要点

1. **响应驱动刷新**：凡改变后端状态的操作，以响应中的 workflow_current 收敛
   本地镜像；`workflow.changed` 通知只作广播冗余。曾依赖通知，偶发丢失导致
   「删除不刷新」「写入节点列表不动」。
2. **通知处理隔离**：handleNotification 外层 try/catch——单条通知异常不打死
   后续通知。
3. **热键屏蔽**：输入框聚焦时忽略 hotkey.triggered（用户在打字时 F10 不应抢焦点）。
4. **事件流性能**：5000 条截断 + 仅渲染最近 200 条 + 录制事件 100ms 批量推送。
5. **后端告警要能被用户看见**（F-UI-13）：后端（尤其 `core.vision`）的 WARNING 只进
   `~/Library/Logs/autoflow-tauri.log`，那份日志是逐帧 RPC 收发记录、不含诊断字符串，
   用户「为什么没匹配上」只能自己翻日志。现由后端 `log.warning` 通知送来，
   前端存 `backendNotes` 并**同时**做两件事：诊断面板成块显示（可整段复制），
   以及**仅在当前无横幅时**弹一条 warn 横幅——已有 error 横幅时不能覆盖
   （告警是补充信息，不是更高优先级）。
   注意 `log.warning` 是可丢类通知（见 rpc-protocol.md 设计要点 4），
   所以它**只能**作为「锦上添花」的诊断线索，前端不得依赖它收敛任何状态。
6. **画布是「投影」，不是第二份真源**（F-UI-02）。`vNodes` / `vEdges` 两个 computed
   把 store 里的工作流投影成画布要的形状，任何交互都发 RPC、等响应回来再刷新，
   **不做乐观修改**——乐观改边之后如果后端拒绝（自环、节点已删），画布会停在和
   后端不一致的状态。
   两个必须的实现细节：
   - **每次投影都重建新对象**。Vue Flow 会往收到的节点上挂 `dimensions` /
     `selected` / `handleBounds` 等字段，直接传 store 里的对象等于让库改真源。
   - **手柄位置靠 `position: relative` 的行容器**。多出口节点的每个出口是一行，
     手柄绝对定位在行右端（库自带的 `.vue-flow__handle-right` 就是
     `top:50%; right:0; translate(50%,-50%)`，相对最近的定位祖先生效）。
     不用覆盖库的样式，也就不会随库升级失效。
7. **`start` 不渲染入手柄、`end` 不渲染出手柄**，所以这两类边在画布上根本连不出来。
   比「连上再报错」好：用户的意图是明确的，不该让他先犯一次错。
   自环由 `isValidConnection` 拦掉（后端也会拒，但在那里拒是「先连上再被弹回」，
   画布会闪一下）。**没有别的额外规则**——不在前端拦后端允许的东西，
   否则用户会遇到「后端接受、界面拒绝」的困惑。
8. **画布那一列自己管滚动**。`.af-flow-col` 是 `display:flex` + `overflow:hidden`，
   不能沿用 `.af-col` 的 `overflow-y:auto`：让外层滚动会把画布一起滚走，
   而画布要的是「固定大小 + 内部平移缩放」。
9. **新节点落在当前视口中心**（F-UI-02）。画布可以平移缩放，固定坐标在用户把视野
   挪走之后会落在屏幕外——表现就是「点了添加，什么都没发生」，而节点其实加上了。
   屏幕坐标 → 画布坐标 = `(屏幕中心 - 视口平移) / 缩放`，再按已有节点数错开一点，
   避免连点添加时叠成一个点。
10. **旧文件迁移提示是可关闭的、且只弹一次**（F-UI-15）。后端把 v3 的线性列表接成
    线性边链，但 `run_when` 的门控语义无法一对一映射成边，用户必须知道要去重连。
    两个细节：只在标记「从否变是」时弹（否则改个参数就会重新弹出来，等于关不掉）；
    换成非迁移工作流时撤掉（否则提示会一直说上一个工作流的事）。

## 已知问题

- WebView 输入框无法被系统级合成键盘可靠注入（自动化测试限制，人工输入正常）。
- 断连重连后 2s 内的 UI 状态可能短暂陈旧（依赖后端重连握手重放 workflow.current）。
- workflow.changed 通知经 Tauri 事件转发偶发丢失（未定位帧级原因）——结构操作
  已全部改为响应驱动刷新，通知丢失不再影响 UI。
- **画布没有框选、复制粘贴、对齐吸附**，节点多了以后手工摆位比较累。
- **组件渲染没有测试覆盖**（无 WebView 环境），画布的行为只能靠真机验证；
  能单测的部分（出口名、摘要、store 动作）都尽量下沉到了 `src/flow/` 与 store。
- 引入 @vue-flow/core 后 bundle 从约 1.0 MB 涨到 1.63 MB（gzip 443 KB）。
  桌面应用从本地加载，可接受。
